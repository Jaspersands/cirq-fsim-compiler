Two-qubit gates from FSim interactions

Superconducting processors with tunable couplers implement the fermionic-simulation gate FSim(θ, φ). cirq-fsim-compiler decomposes any two-qubit unitary into FSim gates and single-qubit rotations by numerical optimisation, either with free angles or with the one gate a calibrated coupler performs, and compiles whole Cirq circuits the same way.

The first part of this page summarises the results of version 0.5: how it compares with Cirq's own decompositions, and the fewest gates each target needs. The second part runs the decomposition in the browser for a gate you choose and writes the result as OpenQASM 3.

Against Cirq's built-in decompositions

Cirq decomposes any two-qubit unitary into CZ or √iSWAP gates in closed form. Those routines are exact, reach the minimum gate count and take one or two milliseconds. On those two gate sets this package gives the same counts and is slower: the median is 7.8 against 1.4 ms per target for CZ, and 11 against 0.7 ms for √iSWAP.

The difference is on a calibrated gate that is neither. On Sycamore's FSim(π/2, π/6) a generic two-qubit unitary takes three gates, against four from the cirq-core routine and six from cirq_google, which decomposes through CZ at two Sycamore gates per CZ.

Whole circuits go through cirq.optimize_for_target_gateset on the Cirq side, with all-to-all connectivity, and every compiled circuit is equivalent to its input. On CZ and √iSWAP the eleven-circuit suite takes 126 and 159 gates with either compiler, because Cirq also merges blocks there. On Sycamore it takes 171 gates, against 202 from cirq_google and 192 from the cirq-core baseline. The difference comes from the four random circuits, whose merged blocks are generic; on the other seven the counts are equal or the cirq-core baseline is one or two higher. With a per-gate error of 0.62%, the estimated circuit fidelity on Sycamore averages 0.909, against 0.894 and 0.899.

Where it does worse:

  • Speed. Per two-qubit target, Cirq's analytic routines take 0.7 to 3.6 ms (median by gate set) and this package 6.4 to 11 ms; cirq_google takes 7.9 ms. For whole circuits the medians are 20 to 27 ms in exact mode and 35 to 83 ms in noise-aware mode, against 13 to 15 ms for Cirq and 20 ms for cirq_google.
  • Guarantees on Sycamore. Cirq's four-FSim routine uses four gates for every target, and that is guaranteed. This package's count is the proven minimum, but the decomposition at that count is found by search. The four-FSim routine is the fallback at four gates, and a result that misses the tolerance issues a SynthesisWarning; none did in this benchmark.
  • Exactness. Results are converged to a tolerance (here 1e-9; the worst case reached 1e-12), not to machine precision.
  • On CZ and √iSWAP there is no count advantage.

Minimum counts from the Weyl chamber

Every two-qubit gate is k₁ exp(i(x XX + y YY + z ZZ)) k₂ with single-qubit layers k₁ and k₂. The coordinates, canonicalised to π/4 ≥ x ≥ y ≥ |z|, label the gate up to single-qubit gates, and the fewest native gates that can make it depends only on them. Version 0.5 reads that number off before it searches and starts the search there. For CZ, √iSWAP and free angles it has a closed form.

Sycamore, exactly

For any other fixed FSim the count comes from the monodromy polytope (Peterson, Crooks and Smith 2020). A target is made by n copies of a native gate exactly when there is a chain of n − 2 intermediate classes with every step inside the polytope, which is a set of linear inequalities. For FSim(0, φ) and FSim(π/2, φ) the regions have a closed form (Peterson, Bishop and Javadi-Abhari 2022); for every other angle the package solves small linear programs. Sycamore's gate is SWAP times a controlled phase of strength 5π/24, and three of them reach exactly the classes with x + y + |z| ≥ π/8.

Four Sycamore gates are therefore needed only for weakly entangling classes with z ≠ 0 and x + y + |z| < π/8, about 1 in 7,300 of the Haar measure. Cirq's four-FSim routine uses four gates for every target. This package uses three on everything else, and three is the minimum there. The last preset below, exp(i(0.1 XX + 0.05 YY + 0.02 ZZ)), lies in the four-gate region: its best three-gate fit has process infidelity 1.6e-2.

Method
  • Template. Ln·FSim(θn, φn)·…·FSim(θ₁, φ₁)·L₀ with Lk = (Rz·Rx·Rz) ⊗ (Rz·Rx·Rz), six angles per layer. FSim(θ, φ) = [[1, 0, 0, 0], [0, cos θ, −i sin θ, 0], [0, −i sin θ, cos θ, 0], [0, 0, 0, e−iφ]] in Cirq's convention.
  • Loss. 1 − |Tr(Utarget†U)|²/16, which ignores the global phase.
  • Optimiser. BFGS with backtracking and numerical gradients, up to six restarts per gate count. With free angles the first restarts start from CZ-like, √iSWAP, iSWAP and Sycamore angles. It runs in a Web Worker. The Python package uses L-BFGS-B with JAX gradients on the same loss, and also offers a Riemannian solver on U(2)⁴.
  • Weyl coordinates. From the eigenvalues of UBTUB, with UB the target in the magic basis after scaling to determinant one, then mapped into π/4 ≥ x ≥ y ≥ |z| with Cirq's convention. The minimum counts use the closed forms above, and for FSim(0, φ) and FSim(π/2, φ) couplers the closed-form regions of Peterson, Bishop and Javadi-Abhari. For other fixed angles the package solves linear programs over the monodromy polytope; this page does not. On the presets, 40 Haar-random targets and 20 random FSim products the coordinates agree with the package to 10⁻¹⁵, and the counts agree on every target.
  • Calibrated mode. The FSim angles are constants, and only the 6(n + 1) single-qubit angles are optimised. This is why a CZ needs two Sycamore gates and a SWAP needs three.
  • Random unitaries. Gram–Schmidt on a complex Gaussian matrix with random column phases (Haar measure), seeded for reproducibility.
  • Not on this page. The package's noise-aware mode, which uses fewer gates when the approximation error is smaller than the error of the gates it saves, and the comparison with Cirq, which runs in Python (cirq-fsim compare).
  • OpenQASM. Written from the fitted angles. gate fsim is defined with standard gates, as exp(−iθ/2 (XX + YY)) followed by cp(−φ), so any OpenQASM 3 simulator can run the file. The Python package also parses OpenQASM 3 back into Cirq and compiles three-qubit gates with two-qubit block consolidation and routing.
